# ez-skills

This repository is public: every file and every commit message is visible to
anyone.

## Commit messages

- Say what the commit changes: the skill, setting or file, and what it does
  now. Present tense, plain words.
- Never say why it was made, where it came from, or what it was copied,
  ported or adapted from.
- Never name private installs, machines, folders, projects, clients or
  internal tools.
- Subject: `<skill or area>: <what changed>`. Add a body only to list more of
  what changed (settings, behavior), never history or reasons.
- Keep the `Co-Authored-By` trailer.

Good: `check-code skill: DRY, SSOT and best-practice audit of changed or named code`

Bad: `check-code: ported from my other setup so it works without private paths`

## Files

- Skills, README and manifests follow the same rule: no private paths,
  installs, projects or people. Personal values are plugin settings
  (`userConfig`), filled in outside this repository.
- Examples use generic names (`shop-web`, `Alex`, `INC-1001`).
